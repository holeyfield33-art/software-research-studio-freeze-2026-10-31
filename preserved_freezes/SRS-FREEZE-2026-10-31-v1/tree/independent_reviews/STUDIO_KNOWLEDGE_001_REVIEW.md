| Priority | Finding | Proof / impact | Required response |

| P1 | Category overviews are not actionable instructions | Each of the 10 `recommended_actions_or_practices` is simply its own description | Write actual conditional actions and exclusions, each linked to evidence and verification |
| P1 | Relationship contract is missing | There is no separate relationship schema; generic knowledge schema is not suitable for typed `from`/`to`/`relation_type` edges | Define and validate a proper edge schema; specify allowed relation types and endpoint types |
| P2 | Mutable repository evidence | Two source URLs reference `main` branches (`build.sbt`, urllib3 `pyproject.toml`) | Pin to commit SHA and file path, record retrieved revision and access date |

| P2 | Generic evidence fields | Source `supported_claims` repeats broad description; evidence class is free text | Use claim-to-source mappings and controlled evidence classes; distinguish guidance, observation, execution, inference |
| P2 | Reproducibility / output protection | Absolute `/home/ubuntu` path hardcoded in seed script; no manifest/hash tracking of evidence | Adopt relative paths, snapshots/commit hashes, deterministic builds, immutable source references |

## Release gates

1. **Integrity gate:** non-destructive generation, stable IDs, schema validation, cross-file references, no duplicate keys, and repeatable manifest checks.
2. **Evidence gate:** every normative or implementation claim backed by precise primary/repository evidence; mutable references pinned; missing evidence marked INFERENCE or UNVERIFIED.
3. **Usability gate:** from user requirements and a software category, a reviewer can trace recommended stages, design choices, prompts, roadmap dependencies, gates, and evidence without inventing defaults.
4. **Calibration gate:** compare outputs for a small Web/API project, an AI agent/security project, and a CLI/library project. Ensure exclusions work, and high-risk controls are not applied as unconditional boilerplate.
5. **Boundary gate:** no modification of Studio, Block-Wise, or other products; deliver research artifacts only until reviewed.
